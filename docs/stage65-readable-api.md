# Stage 6.5 implementation

The public catalog is `runtime/public-api.json`; `DepositAPI` exposes its positional, token-last procedures. Public result classes are separate from internal outcomes, preserving portable receipt and history information while returning only the documented native/scalar/structured columns. `SessionActionService` coordinates authentication, transaction-captured session observations, nonblocking token mutation leases, explicit refresh, prepared recovery and diagnostics. `ArgumentService` normalizes selectors through repositories and binds immutable identities, including existing selectors in batches. Domain services retain their existing validation and action boundaries.

`PreparedActionRepository` persists version 1 preparations separately from mutations: generated operation identity, actor/scope, original preconditions, selector bindings and a keyed argument fingerprint. It stores no complete argument payloads or session credentials. Actor locks precede prepared-action and scope locks. Status waits for active execution before consulting the atomic receipt. Startup recovery relies on Neo4j transaction recovery plus existing OCFL reconciliation: committed receipts survive; an interrupted uncommitted attempt retains only its preparation. The server epoch precondition prevents uncommitted server actions from executing in a different run.

Session baselines publish only after commit. Existing observations remain pinned, successful domain commits advance their own scope, refresh explicitly adopts current revisions, and receipt replay does not adopt intervening changes. A transaction retains its captured observations even if a concurrent read or refresh completes. One token rejects overlapping mutations; independent edit views use independent tokens. Selection and session controls require separate transactions.

`CorpusTransport` is test-only migration infrastructure. Existing scientific fixture maps become positional wire arguments; prepared actions provide retry identity, explicit `toData` and receipts reconstruct portable assertion values. It is not a supported public envelope or client wrapper. `Stage65CoreIT` uses raw positional Cypher independently, checking exact registered signatures/modes/columns and the new state machine. Recovery suites and the existing probes exercise the installed server and actual process termination.

Run `scripts/Invoke-Stage65Gate.ps1 -RunPrefix <fresh-id> -Port 17770`. The gate preserves accepted Stage 0-6 checkpoints, captures current source inputs, checks catalog/documentation, and runs cumulative normal/probe, crash, restart, backup/restore and CLI interruption/resumption evidence on the single authorized installation. Only a passed dedicated checkpoint marks acceptance. See the hub status document for the current result. Stages 7-11 and executable Python/GUI clients remain pending.
